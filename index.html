    03 / 协作设计

    分清职责，也划清交接的线。

    点击一个岗位，查看它接什么、交什么，
    以及什么时候才能开工。

    A

    可以并行的，同时推进

    图卡和配音各自接收明确输入，可以独立制作；剪辑等待两路已审核材料齐备。

    B

    交付成品，减少内部依赖

    删除剪辑反查配音制作历史的依赖，改用完整音频、朗读稿和字幕对应资料交接。

    C

    局部修改，完整交接

    返工只改目标部分；审核后交给下游的是最新完整材料，避免新旧版本混用。

    05 / 能力边界

    能做到哪里，就展示到哪里。

    已有真实记录

    内容制作与协作

    • 四岗位协作，图卡与配音并行
    • 图卡定向修改、两图合一后完整交接
    • 指定时间局部重配，保留其他好片段
    • 人工审核、正式交付与成片验收

    不同能力对应不同案例，不表示全部异常分支均已验证。

    仍由人决定

    质量与重要操作

    • 确认最终稿和配音朗读稿
    • 审图、试听，决定是否通过
    • 检查成片，并手动上传发布
    • 程序故障时与 Codex 排查、验收修复

    日常审核与故障修复，是不同的人工介入。

    验证范围有限

    不扩大已经完成的事

    • 已验证同类 Python 内容流程复用
    • 跨行业迁移尚未验证
    • 陌生人独立部署尚未验证
    • 整机断电恢复、云端无人值守尚未完整验证

    公开网页的上线，不等于生产 Agent 已部署到云端。
