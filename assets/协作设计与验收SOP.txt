多 Agent 协作设计与验收 SOP

项目展示版
更新日期：2026年10月30日

这份标准操作流程根据已运行的 Python 知识讲解视频项目整理，记录从确定交付目标、拆分岗位，到交接、返工和验收的做法。适用于本项目及同类内容流程的设计与检查；日常开工和审核操作另见配套使用说明书。

我的贡献：定义各岗位的输入输出、职责和开工条件，安排并行与等待关系，设置人工审核，并负责结果验收。代码实现、排错与测试借助 Codex 完成。

一、确定任务范围

具体动作：先列出已有材料、最终要交付的成果，以及需要人工完成的部分。本项目从已确认的最终讲解稿和配音朗读稿开始，产出图卡、完整配音和带字幕的视频；发布由本人完成。内容生产助手负责选择现有稿件，缺稿或篇目不明确时先补齐或选择，不自行猜写内容。

留下什么：输入输出清单、人工负责事项、适用范围。

完成条件：可以明确回答“这次做哪篇、用哪份稿、最后交什么、谁来审核和发布”。

二、拆分岗位，写清开工条件

具体动作：逐个列出岗位接收什么、交付什么、什么条件下开始，确认上游交出的东西足够下游使用。本项目分工如下。

内容生产助手
接收什么：用户的开工、选稿要求及已确认稿件
交付什么：同一篇任务分别派给 Python 图卡员和配音员
开工条件：篇目确定，所需稿件齐备并核对通过

Python 图卡员
接收什么：最终讲解稿及图卡任务
交付什么：候选图片供审图；通过后向剪辑员交付最新完整图组
开工条件：收到明确派发，所需输入可用

配音员
接收什么：配音朗读稿及配音任务
交付什么：候选音频供试听；通过后向剪辑员交付完整音频及字幕所需资料
开工条件：收到明确派发，所需输入可用

剪辑员
接收什么：已通过的图组、完整音频、朗读稿和字幕对应资料
交付什么：带字幕的成片及视频附件，交人工验收
开工条件：两路均已通过，任务、版本和材料齐备情况核对通过

留下什么：岗位分工说明。

完成条件：每一项输出都有明确接收方，每个岗位知道何时开始、何时交出结果；审图、试听和成片验收由人工负责。

三、安排并行、等待和交接

具体动作：根据材料依赖安排执行顺序。图卡制作和配音可以同时进行；剪辑必须等待两路材料通过审核。将下游需要的正式交付物与上游内部的制作过程分开。

剪辑开工前核对三项：

任务对应：图片、音频及配套资料属于同一篇任务。
版本对应：收到的是各自当前已审核通过的版本，文件与交付清单对应。
材料齐备：最新完整图组、完整音频、朗读稿和字幕对应资料均已交齐；字幕对应资料用于说明朗读内容与音频片段的对应关系。

缺少材料时继续等待；发现材料不对应时先处理交接问题。配音内部的生成尝试和旧片段来源由配音员负责核查，剪辑依据正式交付材料制作视频。

留下什么：主流程图、交接材料清单和开工条件。

完成条件：图卡与配音可独立推进；两路审核通过且材料核对无误后，剪辑能够接手，不需要人工搬运文件或翻查配音内部制作历史。

四、设置人工审核和返工步骤

具体动作：把人工判断安排在两处，并明确不通过时退到哪里。

人工卡点一：审图、试听。本人检查图卡内容、代码与结果是否对应、文字是否可读；试听完整音频，检查漏读、卡顿和变形。有问题就向对应岗位说明目标图片或音频时间位置，修改后重新审图、试听。

人工卡点二：成片验收。本人检查画面、配音、字幕是否对应，播放是否完整。通过后确认成片，再由本人上传发布；未通过则说明问题位置，交相应环节处理。

局部返工先确定任务和当前版本，保留未改部分及旧候选。只改一张图时可只发该图供审核，但向剪辑交付的是最新完整图组；合图后核对图片数量和清单；局部重配后交付重新拼好的完整音频及相应字幕资料。

留下什么：审核意见、修改后的候选、正式材料清单和人工通过记录。

完成条件：修改目标正确，未改部分保留，旧材料没有混入新交付；修改后的材料经人工确认后继续向下游推进。

五、测试结果，按证据处理问题

具体动作：根据本轮改变检查受影响的环节。普通新篇核对从派发到图卡、音频、成片实际送达；返工还要核对完整材料是否正确交给剪辑，最终能否完成成片。

出现异常时，先核对该任务的记录、真实文件和错误。等待人工审核与程序失败分开判断；已确认的失败交负责该环节的 Codex 项目修复。修复前保留原版，修复后检查相关流程；真实重试、恢复和生产由用户在飞书触发。需要回退时先核对是否有后续修改，避免覆盖新成果。

留下什么：测试输入、实际产物、送达与审核记录；发生修复时补充原因、修改范围、验证结果和回退说明。

完成条件：能用文件和记录证明结果，区分离线测试、修复后通过与正常生产通过；未完成的验证明确保留，不用一句“成功”代替检查。

六、整理方法，再用下一篇验证

具体动作：将已经验证的岗位分工、交接条件、审核和返工做法整理进说明，附真实案例；流程改变时同步更新对应部分和日期。下一篇同类内容沿用已确定的协作流程，再核对实际结果。

留下什么：SOP、使用说明书、真实样例和已有项目记录。

完成条件：下一篇同类内容能按既定分工和审核方式完成；可以查到本次输入、产物、人工结果，以及是否发生中途修复。换内容类型或业务时，重新确认输入输出、角色和验收要求。

真实案例与证据
